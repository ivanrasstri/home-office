# Pitchdeck web export — сервер

Принимает презентации, опубликованные из `../figma-plugin` (кнопка
«Опубликовать» → сервер → shareable-ссылка), отдаёт их как HTML-слайд-шоу и
считает простую аналитику просмотров. Это самостоятельный сервис, не связанный
с ботом поиска работы (`jobbot`) — просто живёт в том же репозитории.

## Локальный запуск

```bash
pip install -r ../requirements.txt
export PITCHDECK_API_TOKEN=любая-длинная-случайная-строка
python -m pitchdeck_server
# слушает :8000 (или $PORT)
```

Проверка:
```bash
curl -X POST http://localhost:8000/api/decks \
  -H "Content-Type: application/json" \
  -H "X-API-Token: $PITCHDECK_API_TOKEN" \
  -d '{"title":"Test","slides":[{"width":1280,"height":720,"elements":[]}]}'
```
Ответ содержит `url` (публичный просмотр) и `analytics_url` (просмотры,
защищён токеном владельца из самой ссылки).

## API

- `POST /api/decks` — заголовок `X-API-Token: $PITCHDECK_API_TOKEN`, тело
  `{title, slides: [{width, height, elements}]}` — `elements` в том же
  формате, что уходит в PPTX (`figma-plugin/src/shared.ts`): `text` (runs с
  шрифтом/цветом/bold/italic), `shape` (rect/roundRect/ellipse/line с
  заливкой и обводкой), `image` (data-URL PNG). Возвращает `{id, url,
  analytics_url}`.
- `GET /p/{id}` — HTML-просмотрщик: слайды рендерятся из тех же элементов
  прямо в DOM (не картинками), с масштабированием под окно и навигацией
  (стрелки, клик по половинам экрана, свайп не реализован).
- `POST /api/decks/{id}/track` — вызывается самой страницей просмотра
  (`navigator.sendBeacon`) на открытие и на каждую смену слайда (с
  временем, проведённым на предыдущем).
- `GET /p/{id}/analytics?token=...` — просмотры по дням и по слайдам.
  `token` — `owner_token`, который выдаётся один раз при публикации и живёт
  только в `analytics_url` (потерял ссылку — потерял доступ, пересоздавать
  токены пока негде).

## Хранилище

SQLite-файл `PITCHDECK_DATA_DIR/pitchdeck.db` (по умолчанию
`pitchdeck_data/pitchdeck.db` — **не** `data/`, потому что тот каталог
джоб-бот коммитит обратно в репозиторий, а презентациям там не место).
На Railway — путь к примонтированному Volume, иначе презентации и аналитика
исчезнут при передеплое.

## Деплой на Railway (второй сервис в этом же репо)

1. В том же Railway-проекте, где уже крутится `jobbot` worker: **New →
   GitHub Repo** → тот же репозиторий, как отдельный сервис.
2. **Settings → Deploy → Start Command**: `python -m pitchdeck_server`
   (переопределяет `railway.json`, который по умолчанию настроен на
   telegram-бота).
3. **Variables**: `PITCHDECK_API_TOKEN` (тот же секрет указываешь в UI
   плагина), опционально `PITCHDECK_BASE_URL` (если автоопределение домена
   по запросу даёт не то).
4. **Volume**: примонтируй, например, в `/data`, и поставь
   `PITCHDECK_DATA_DIR=/data`.
5. Railway выдаст публичный домен вида `https://<service>.up.railway.app` —
   его и вставляешь в поле «Адрес сервера» в плагине.

## Ограничения

- Один общий `X-API-Token` на всех, кто публикует (без учёток и мультитенантности)
  — рассчитан на личное/командное использование, не на публичный SaaS.
- Шрифты в вебе рендерятся через CSS `font-family` — если у зрителя нет
  точного шрифта из Figma, браузер подставит похожий системный.
- Аналитика простейшая: только счётчики просмотров и среднее время на
  слайде, без разбивки по устройствам/странам/уникальным пользователям.

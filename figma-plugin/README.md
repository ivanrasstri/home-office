# Export to PDF & PPTX — плагин Figma

Альтернатива `../figma_export` (CLI + Figma REST API): работает прямо внутри
Figma, без токена и внешнего скрипта. PDF — растровый рендер каждого слайда
(как обычно и ожидается от PDF-экспорта). **PPTX — не картинка на весь
слайд**: плагин обходит дерево узлов каждого фрейма и создаёт настоящие
редактируемые элементы PowerPoint — текстовые блоки (с шрифтом, размером,
цветом, bold/italic по каждому куску текста) и фигуры (прямоугольники,
скруглённые прямоугольники, эллипсы, линии — с заливкой и обводкой).
Картинкой становится только то, что действительно нельзя честно
векторизовать: иконки/инстансы компонентов, векторные фигуры, заливки-
изображения, градиенты, несколько заливок сразу, тени/блюры. Сеть плагину не
нужна (`networkAccess: none` в манифесте) — вся сборка PDF/PPTX (`pdf-lib` +
`pptxgenjs`) происходит локально в браузере плагина.

## Сборка

```bash
cd figma-plugin
npm install
npm run build       # генерирует code.js и ui.html из src/
```

`code.js` и `ui.html` — сборочные артефакты, в git не хранятся (см.
`.gitignore`) — их нужно собрать локально перед запуском.

## Запуск в Figma

1. Figma desktop app → меню **Plugins → Development → Import plugin from
   manifest…**
2. Выбери `figma-plugin/manifest.json`.
3. Открой файл со слайдами → **Plugins → Development → Export to PDF & PPTX**.
4. Выдели фреймы-слайды (или ничего не выделяй — возьмутся все фреймы текущей
   страницы), задай масштаб рендера и нажми «Экспортировать» — браузер
   скачает `<имя файла>.pdf` и `<имя файла>.pptx`.

## Как устроено

- `src/code.ts` — главный поток плагина (песочница Figma, доступ к
  `figma.*`): находит фреймы-слайды, для каждого рендерит полный PNG (для
  PDF) и вызывает `buildSlideElements` (для PPTX).
- `src/elements.ts` — рекурсивно обходит детей фрейма и для каждого узла
  решает, во что его превратить:
  - `TEXT` → текстовый элемент. Стили читаются через
    `node.getStyledTextSegments()`, так что разное форматирование внутри
    одного текстового блока (bold-кусок, другой цвет и т.п.) сохраняется
    отдельными "run"-ами.
  - `RECTANGLE`/`ELLIPSE`/`LINE` с одной сплошной заливкой и без эффектов →
    фигура pptx (`rect`/`roundRect`/`ellipse`/`line`) с заливкой и обводкой.
  - `FRAME`/`COMPONENT`/`GROUP` → не самостоятельный элемент, а контейнер:
    если есть сплошной фон — добавляется фоновый прямоугольник, затем
    рекурсия по детям.
  - Всё остальное (векторные фигуры, `INSTANCE`, изображения-заливки,
    градиенты, несколько заливок, тени/блюры) → рендерится в PNG именно этот
    узел (`node.exportAsync`) и вставляется как элемент-картинка на своём
    месте — а не как один скриншот на весь слайд.
  - Позиция и размер каждого элемента считаются через `absoluteTransform`
    относительно фрейма-слайда (работает и для повёрнутых объектов).
  - Если в слайде более 400 узлов — обход останавливается и слайд целиком
    откатывается на один растровый элемент (иначе pptx стал бы неподъёмным).
- `src/ui.ts` — UI-поток (обычный браузерный iframe, без доступа к
  `figma.*`, зато есть DOM/Blob): для PDF просто кладёт присланные PNG по
  странице через `pdf-lib`; для PPTX проходит по списку элементов каждого
  слайда и добавляет их через `pptxgenjs` (`addText`/`addShape`/`addImage`).
  У презентации один общий размер слайда (берётся самый крупный фрейм);
  слайды другого размера масштабируются и центрируются в этот холст, поэтому
  относительное расположение элементов внутри слайда не искажается.
- `scripts/build-ui.js` — бандлит `ui.ts` вместе с зависимостями в один JS и
  встраивает его в `src/ui.template.html` → `ui.html`, потому что манифест
  плагина не разрешает грузить внешние `<script src>`.

## Ограничения

- Экспортируются только фреймы/компоненты верхнего уровня как слайды —
  внутри слайда разбор идёт вглубь по всем детям.
- Векторные фигуры, инстансы компонентов, изображения и сложные эффекты
  (тени, блюры, градиенты) в PPTX остаются картинками — честно
  векторизовать их через pptx-фигуры невозможно, зато текст и простые
  прямоугольники/эллипсы/линии — полноценные редактируемые элементы.
- Поворот у элемента внутри повёрнутой группы может отрисоваться неточно
  (используется собственный `node.rotation`, без накопления поворотов
  предков) — для типичной раскладки слайдов (сами слайды не повёрнуты) это
  не встречается.
- Размер слайда в PPTX ограничен максимумом PowerPoint (56 дюймов) —
  для типичных Figma-фреймов (1280×720 и подобных) это не проблема.
